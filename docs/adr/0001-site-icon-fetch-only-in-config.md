# ADR 0001：站点图标仅在配置时获取

- **Status:** Accepted
- **Date:** 2026-07-20

## Context

书签与服务条目需要图标。现有能力支持手填 `mdi`/`si`/URL/`/images`/`/icons`，以及编辑器上传到 `config/images`。缺图标时目前回退到书签 `abbr` 或名称首字母。

期望增加「从目标网站取图」：既希望配置时能一键拉取，也曾考虑仪表盘在缺图时自动请求目标站。需要决定取图发生在哪条路径、结果是否写配置、以及和上传模型如何共存。

## Decision Drivers

- 配置文件的变更应可预期、可审阅，不能因打开仪表盘而静默改写 YAML
- 首页大量指向内网 NAS、路由器、*arr 等，取图必须能打内网，且常遇自签证书
- 避免仪表盘每次渲染对多台内网设备发起爬取（性能、目标站压力、SSRF 面暴露在只读路径）
- 与现有「上传 → `/images/...` → 保存写回」编辑模型一致
- 实现与运维复杂度可控

## Considered Options

1. **展示期服务端代理 + 可选写回**  
   仪表盘缺 icon 时由服务端按需抓取并缓存；用户可在编辑器「采用」写入 YAML。

2. **双路径**  
   展示代理只做短时/磁盘缓存且永不写配置；编辑器「获取」另下载并写回 `icon`。

3. **仅配置时获取（本决策）**  
   仪表盘从不因缺 icon 出网。只有编辑器显式「获取」才解析站点、导入本地图并填入表单 `icon`，经保存写入 YAML。

4. **保存配置时自动为缺 icon 条目获取**  
   隐式、难撤销、保存延迟不可控。

## Decision Outcome

选择 **选项 3：仅配置时获取**。

配套规则（与 glossary 一致）：

- 无可用 Icon（未配置或坏图）→ **Generic Icon Placeholder**（书签/服务一致）；`abbr` 保留字段但不参与图标回退
- 「获取」= **Icon Resolve**（列候选 + 内嵌预览）→ 用户必选（含单候选）→ **Icon Import**（从短时会话缓存落盘 `/images/...`，只改表单）
- 取图源为条目完整 `href`；无 `href` 不可获取
- 回退链：apple-touch-icon → rel=icon → `/apple-touch-icon.png` → `/favicon.ico`
- 服务端执行；放行内网；取图路径忽略 TLS 证书错误；仅同 host 重定向；匿名、不带条目凭证
- 已有 icon 时获取须确认覆盖；旧本地文件不自动删
- 超时/体积取宽松内网档（约 15s，HTML ≤2MB，图 ≤5MB，与上传上限对齐）

### Positive Consequences

- YAML 只在用户保存时变化，行为可审阅
- 只读仪表盘不出网爬站，攻击面与负载更小
- 导入结果与上传资产同一模型（`/images`），离线可显示
- 编辑器流程与「上传图片」心智接近，仅多一步站点候选挑选

### Negative Consequences

- 新建大量条目时需逐条点获取（本 ADR 明确不做批量）
- 站点更换 favicon 后不会自动更新，需用户再次获取
- 展示期无法「零配置也出站标」，缺图时只有通用占位
- 取图忽略 TLS 校验 + 放行内网，要求部署方信任运行 homepage 的网络位置

## Pros and Cons of the Options

### 选项 1：展示代理 + 可选写回

- 好：零配置也有站标；写回仍可选
- 坏：必须设计正/负缓存与失效；只读路径承担 SSRF 与内网爬取；和「配置为真源」张力大

### 选项 2：双路径

- 好：展示有图且 YAML 不被静默改写
- 坏：两套取图语义与缓存；实现与测试面加倍；用户难理解「为何编辑器里还是空的」

### 选项 3：仅配置时获取

- 好：真源清晰；与上传模型统一；仪表盘简单
- 坏：无自动站标；逐条操作

### 选项 4：保存时自动获取

- 好：少一次点击
- 坏：保存变慢且副作用重；部分失败难报告；违背显式获取

## Notes

实现阶段若恢复「展示期取图」，应另开 ADR 废止或修正本文，而不是静默加回。
